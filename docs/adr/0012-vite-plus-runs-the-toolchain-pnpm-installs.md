# Vite+ runs the toolchain; pnpm installs

The repository moves from Bun to pnpm for installing dependencies, and from separately pinned tools to Vite+ (`vp`, the `vite-plus` package) for testing, formatting, linting, staged-file checks, Git hooks, and the task runner. This supersedes [ADR 0011](0011-bun-installs-node-runs-npm-publishes.md) where the two disagree. ADR 0011's Typechecker section, its type-aware lint backend, its publish manifest, and its vscode-js-debug fixture still hold, with the amendments below.

## Decision

**Package manager.** pnpm 12 installs, from `pnpm-workspace.yaml` with `packages/*`. `pnpm-lock.yaml` replaces `bun.lock`, and `bunfig.toml` is deleted. `linkWorkspacePackages: true` is required: packages depend on `@ian-pascoe/pi-utils` through a semver range, not `workspace:`, so that published manifests stay installable, and pnpm resolves such a range from the registry unless told to link. `allowBuilds` replaces root `trustedDependencies` with the same four packages allowed and `tree-sitter-bash` and `zeromq` denied, as before ADR 0011. pnpm 12's default `minimumReleaseAge` (1440 minutes) matches the one-day delay `bunfig.toml` set, so it is not configured. `devEngines.packageManager` names `pnpm` `^12.18` with `onFail: "ignore"`, and `mise.toml` pins Node, pnpm, and `viteplus` (mise's name for `npm:vite-plus`) at the version the root depends on.

The lockfile was resolved afresh: pnpm cannot import `bun.lock`. Most versions match `bun.lock`; the rest moved within their ranges, by patch or minor releases, mostly in tools that `vite-plus` now replaces. The Pi SDK was pinned for one install so that root `@earendil-works/pi-ai`, `pi-agent-core`, and `pi-tui` resolve to 1.5.0, the versions the exact `pi-coding-agent@1.5.0` pins. A fresh resolution picked 1.5.2 for the root's caret ranges, which installs two copies of each and splits their module state between tests and the coding agent.

**Node.** `mise.toml` pins Node 22.23.5, because `vp staged` needs 22.22.1 or later on the 22.x line. Published packages still declare `node >=22.19.0`; only contributors and CI need the newer version. The newer Node also makes npm 12 (which needs 22.22.2 or later) eligible for the workflows' `npm install --global`, and npm 12 prints `npm pack --json` as an object keyed by package name instead of an array, which the pack check rejects. The workflows therefore install `npm@^11.5.1`, the npm that Node 22.19 resolved `>=11.5.1` to before; moving to npm 12 is separate work.

**Vite+.** `vp migrate` (1.6.0) made the mechanical changes: root `vitest`, `oxlint`, and `oxfmt` became one `vite-plus` devDependency, with pnpm overrides pointing `vite` and `vitest` at Vite+'s copies; imports from `vitest` and `vitest/config` became `vite-plus/test` and `vite-plus`; the anti-slop Oxlint plugin imports `vite-plus/lint/plugins` instead of `@oxlint/plugins`; and `.oxlintrc.json` and `.oxfmtrc.json` merged into the root `vite.config.ts`, which adds the `vite-plus/prefer-vite-plus-imports` rule. `pi-dap` keeps a direct `vitest` because its integration test launches `vitest.mjs` under the debugger. The migrator also gave `pi-bible-verses` one, because its `tsconfig.json` listed `vitest/globals`, a leftover: its tests import from `vite-plus/test` and the shared config does not enable globals, so the entry and the dependency are removed. The root and package `vitest.config.ts` files stay, since Vitest prefers them to `vite.config.ts` and every package config reuses the root one. The skill under `.pi/skills/install-anti-slop` keeps `@oxlint/plugins`, because it installs the plugin into other repositories.

`vp migrate` wrote the toolchain versions as `catalog:` references to a pnpm catalog. They are concrete versions instead (`vite-plus` 1.6.0, `vitest` 5.1.0, and the core alias in the overrides), because Pi installs this repository from Git with npm, which fails on any `catalog:` spec, devDependencies included; the Git-install check caught it. The Vite+ version therefore lives in five places that must move together: `viteplus` in `mise.toml`, `vite-plus` in the root `package.json`, the `vite` override's core alias in `pnpm-workspace.yaml`, and the bundled Vitest version (`vp toolchain` shows it) in the `vitest` override and in `pi-dap`'s devDependencies. Dependabot can update only some of them, so it ignores `vite-plus`, `vitest`, and `@voidzero-dev/vite-plus-core`, and upgrades are made by hand.

**Typechecker.** tsrs stays the only TypeScript gate, as ADR 0011 decided. The `lint` block keeps `typeAware: true` and `typeCheck: false`, so `vp check` formats and lints but does not typecheck; each package's `typecheck` script and the root `typecheck:root` still run `tsrs --noEmit`, and `pi-utils` still builds with tsrs.

**Type-aware lint backend.** tsrslint stays, selected by `OXLINT_TSGOLINT_PATH` from mise's `[env]`; `vp lint` honours the variable. On this repository it took 2.5 s against 7.0 s for the `oxlint-tsgolint` that `vite-plus` bundles, and both reported no diagnostics. The failure mode changes: `vite-plus` depends on `oxlint-tsgolint`, so a shell without mise's environment now lints on that bundled backend instead of failing. ADR 0011 measured identical diagnostics from the two backends, so such a run is slower, not different.

**Task runner.** `vp run` replaces Turborepo, and `turbo.json` is deleted. A `vite.config.ts` task is cached by default; a `package.json` script is cached only when run with `--cache`. The root `typecheck` and `test` scripts pass `--cache` to the nested `vp run` calls, and `verify` and `verify:push` chain them after the `check` task, so verification is cached while `changeset`, `pack:check`, `git-install:check`, and the release scripts never are. A cached command runs with a reduced environment, so the `check` task (`vp check`) lists `OXLINT_TSGOLINT_PATH` in `cache.env`; without it, lint inside `vp run` would silently use the bundled backend. The tests do not depend on the outer environment, because the shared `vitest.config.ts` sets `HOME`, `TMPDIR`, and Pi's agent directory itself.

Vite Task fingerprints the files each command reads, so a package test that reads another package's source is invalidated by a change there, and the hand-maintained cross-package `inputs` in `turbo.json` have no replacement. Changing one `pi-utils` source file re-ran `vp check` and the typecheck of the five packages that read it, `pi-utils` included, and replayed the other fifteen steps of `verify:push`. On macOS that tracking injects a library into every process a cached command starts, through `DYLD_INSERT_LIBRARIES`, and Vite+ 1.6.0 cannot opt a child out. dyld rejects the library in some arm64e system binaries and kills them: `/usr/sbin/lsof` dies, while the `/bin` and `/usr/bin` tools tried (`sh`, `bash`, `env`, `git`, `ps`) run. Pi DAP's Supported Adapter test found its debuggee through `lsof`'s working directory, so it now identifies the debuggee as a descendant of the adapter it launched, which reads only `ps` or `/proc`. A test that needs such a binary fails under `vp run --cache` on macOS only. The cache lives in `node_modules/.vite/task-cache`, which CI restores and saves as it did `.turbo/cache`. `vp run` takes one task per call and runs at most four tasks at once, so `verify` runs check, then typechecks, then tests, where Turborepo ran all three together.

**Hooks.** The Vite+ hook dispatcher replaces Husky. Hooks live in `.vite-hooks/`; the pre-commit hook runs `vp staged`, whose `staged` block in `vite.config.ts` runs `vp check --no-error-on-unmatched-pattern` on staged files without fixing them, as lint-staged did. The pre-push, post-checkout, and post-merge hooks are unchanged apart from `vp run verify:push`. The dispatcher runs each hook with `sh -e` and `node_modules/.bin` on `PATH`, as Husky did. `prepare.mjs` runs `vp config --no-agent --hooks-dir .vite-hooks` on development installs. `vp config` never replaces a `core.hooksPath` it did not set, so first `prepare.mjs` unsets one that still points at Husky's `.husky/_` and deletes that generated directory.

**Runtime guard.** `scripts/assert-node-runtime.mjs` and its call sites are deleted. They existed because `bun run` could start a tool under Bun's runtime; pnpm and `vp` start Node.

**Publish path.** Changesets 3.0.3 publishes with `pnpm publish` when the workspace uses pnpm, as it did before ADR 0011. pnpm applies `publishConfig` field overrides itself, but `publish-packages` still runs `scripts/publish-manifest.mjs apply` first, and `pi-utils`'s `prepack` (now `pnpm run build && …`) still runs `check`: the manifest is then right whichever tool packs it, and a bare `npm publish` still fails. `pack:check` keeps packing with npm.

**Editor integration.** `.pi/settings.json` runs the formatter as `vp fmt`, the oxlint language server as `vp lint --lsp`, and the tsrs language server as `vp exec tsrs --lsp --stdio`, with `vite.config.ts` and `pnpm-workspace.yaml` as root markers.

**CI.** `jdx/mise-action` installs Node, pnpm, and `vp` and exports `OXLINT_TSGOLINT_PATH`. Jobs cache the pnpm store keyed on `pnpm-lock.yaml`, install with `pnpm install --frozen-lockfile`, and run `vp run verify`, `pnpm run pack:check`, and `pnpm run git-install:check`. Dependabot uses the `npm` ecosystem, which covers pnpm, with the same one-day cooldown.

## Considered Options

- **Keep Bun under Vite+.** Rejected: the migration was asked to move to pnpm. Vite+ also documents fewer Bun paths: Bun catalogs resolve only inside a workspace, and Bun needs a mirrored `vite` dependency for its peer resolver.
- **A pnpm catalog for the toolchain versions.** Rejected: npm Git installs reject `catalog:`, as above.
- **Keep Turborepo beside Vite+.** Rejected: it duplicates `vp run`, and its manual cross-package inputs are what Vite Task's file tracking removes.
- **Cache every script (`run.cache: true`).** Rejected: it caches the interactive `changeset` command and the artifact and release scripts, and runs them in the reduced environment.
- **Type-check through `vp check` (`typeCheck: true`) and drop tsrs.** Rejected for now: ADR 0011 chose tsrs on measured speed and parity, and `vp check` would not build `pi-utils`.
- **The bundled `oxlint-tsgolint` backend.** Rejected for now: it was nearly three times slower here, and tsrslint is interim until oxc-project/tsrs#378 anyway.
- **Keep hooks in `.husky/`.** The dispatcher accepts Husky's layout, but a `.husky` directory without Husky misleads; `.vite-hooks` is Vite+'s default.

## Consequences

Contributors run `mise install` for Node 22.23, pnpm, and `vp`, keep mise active in the shell for the tsrslint path, and use `vp run <script>` or the built-in `vp check`, `vp fmt`, `vp lint`, and `vp test`. Linting in a shell without mise's environment is about three times slower instead of failing. A later `vp migrate` may write `catalog:` references again and must be reverted to concrete versions. Pi Guardian's sensitive paths cover `.husky` but not `.vite-hooks`; adding it is follow-up work for that package.
