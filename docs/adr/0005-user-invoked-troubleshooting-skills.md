# Ship troubleshooting Skills as user-invoked and point to them on failure

Every extension package ships one `skills/<package>/SKILL.md` for configuration and diagnosis. Each sets `disable-model-invocation: true`, so Pi keeps it out of the system prompt's skill list. Users still open it with `/skill:<package>` or a `$<package>` Skill Reference. Listing all fourteen Skills on every turn cost about 1.2k tokens and added fourteen "diagnose X when broken" triggers that are irrelevant in healthy sessions; users removed them with package `skills` filters instead.

The model learns about a Skill only when it is relevant. Each package with failures the model can see defines `src/troubleshooting-skill.ts`. That module resolves the Skill's absolute path from `import.meta.url` and exports one hint, `For diagnosis, read the <package> troubleshooting Skill at <path>.` Packages append the hint to model-facing failures the Skill covers, such as tool errors and configuration failures, but not to ordinary input errors. Packages whose failures appear only in the UI (Bible Verses, TPS Tracker, Git Status Widget, Skills Selector, Git Checkpoints) add no model-facing hint. A user notification that is the only place a configuration failure appears ends with `Run /skill:<package> to diagnose.`

The hint also closes a warning when the warning itself asks the model to change configuration or load more of the workspace. pi-lsp's other-roots and unloaded-packages warnings on `lsp_find_references` and `lsp_rename` end with a compact pointer, `(pi-lsp troubleshooting Skill: <path>)`, exported from `src/troubleshooting-skill.ts` beside the hint. The Skill's path stays the module's to resolve; the warnings are not failures, so the pointer is shorter than the hint.

We rejected registering Skills only after a failure through `resources_discover`, because changing the system prompt mid-session breaks prompt-cache prefix stability. We also rejected one shared router Skill: packages install independently, so no package could own it. The pack check requires every package Skill to set `disable-model-invocation: true`. The Git-install check proves that loading all fourteen Skills leaves the session system prompt byte-identical.
