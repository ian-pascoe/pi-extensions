# Decide hard limits by rule, review only what the agent does, and escalate before rejecting

Live use with a small Guardian model (Claude Haiku, thinking off) rejected ordinary workspace work, such as a read-only `grep | head`, a whole-file rewrite, or `git add && git status`, mostly in Child Agents whose detailed task came from the root agent and was therefore untrusted. Following Claude Code's auto mode and oh-my-pi's approval mode, Guardian now splits the decision four ways.

- **Command Rules** (`commands`) replace `safeCommands`: literal command prefixes mapped to `allow`, `review`, or `deny`. Hard limits belong to deterministic rules rather than to the model, so `deny` blocks a matching `bash` segment without a model call. A rule matches only a segment whose leading words are literal, so `deny` is not a sandbox: the Guardian is told the user's `deny` and `review` rules and rates reaching their effect another way as `security_policy`. Safe Commands may be pipelines and lists of Safe Commands.
- **Reasoning-blind evidence**: the Guardian sees the user's messages and the agent's tool calls, read from the session branch so compaction loses neither, but not the agent's text or reasoning, tool results, other extensions' messages, or compaction and branch summaries. These cannot authorize a call and are where injected or mistaken justifications live; a smaller transcript also keeps a small model focused. Context edits are ignored, since evidence records what the user typed and the agent did.
- **Approved delegations**: authorization is established at the handoff. A `subagent` task or `agent_message` message that the delegating session's Guardian reviewed and allowed with at least `medium` User Authorization (a low-risk call allowed without it is not an approval), or its user allowed once, becomes Trusted Evidence in the Child Agent it reached, for the use it was approved for (a task or a Coordination Message), so a parent's Guardian judges whether the task fits the user's request and the child's Guardian judges calls against the task. A delegation allowed by an `allow` Tool Policy was never judged and stays untrusted.
- **Escalation Pass**: a first pass whose assessment the Decision Table would reject is reviewed once more, with the same request plus an instruction to reason carefully, by `escalationModel` at `escalationThinkingLevel`. With the same model the second request reuses the cached system prompt, and the cached messages only with the same thinking settings: a provider such as Anthropic invalidates cached messages when thinking changes, so with a thinking-off first pass the escalation pays for the evidence again. The second assessment decides; if it fails, the Rejection stands. The first pass keeps its calibration rather than being told to block when unsure.

This amends [ADR-0001](0001-review-with-one-stateless-call.md): a review is still stateless and without tools, but a would-be Rejection costs a second completion. We accepted the extra latency on the rare rejected path to spare the common allowed path a slower model.
