# Let a classifier make the First Pass and escalate on Rejection Probability

Pi exposes classifier models such as TypeSafe's Jev through `ctx.modelRegistry.classify()`. They answer typed `choice` questions with calibrated probabilities in well under a second, at a fraction of a language model's cost, but give no rationale. A separate `classifierModel` setting, off by default, lets one make a Guardian Review's First Pass: one request asks three `choice` questions (Risk Level, User Authorization, Risk Category or `none`) whose top answers the Decision Table decides in code. A setting separate from `model` is needed because a llama.cpp model has the same `provider/id` as a chat model and as a classifier, and classifiers are not in the chat model picker. The Escalation Pass is always a language model (`escalationModel`, else `model`, else the session's), sees today's escalation request, and is never shown the classifier's answers.

The classifier is a fast path, not a gate. It escalates when its Outcome would be a Rejection, when its **Rejection Probability**, P(`critical`) + P(`high`) × P(`unknown` or `low` User Authorization), reaches `escalationThreshold` (default 0.2), when it rates `high` or `critical` without a Risk Category (asking the same classifier again would give the same answer, so there is no corrective retry), and when it fails, under a fixed 10-second deadline. We trigger on Rejection Probability rather than the classifier's own `confidence`, which measures how peaked an answer is, so a split between two allowed Risk Levels would escalate for nothing. We rejected an explicit "escalate" option, whose probability no classifier is calibrated for. A failed Escalation Pass never allows: after a would-be Rejection the Rejection stands; after an uncertain, uncategorized, or failed classifier the review is a Review Failure.

This amends [ADR-0003](0003-rules-reasoning-blind-evidence-and-escalation.md): a would-be Rejection still costs a second completion, but a classifier's First Pass also escalates on doubt and on failure, trading a slower uncertain path for a common allowed path that needs no language model.
