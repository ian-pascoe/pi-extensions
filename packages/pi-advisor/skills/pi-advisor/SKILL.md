# Pi Advisor

Use this sequence for a live Advisor problem:

1. Run `/advisor status`. Record the effective settings, each setting's source, review state, backlog, usage/cost, and last error. Treat unknown cost as unknown, not zero.
2. If the state is disabled, check the selected session override, trusted-project settings, and global settings in that order. Advisor defaults to disabled. Use `/advisor on`, `/advisor off`, `/advisor inherit`, or `/advisor set <key> <JSON>` at the intended scope; use `/advisor prompt` for the native prompt editor. Confirm the selected branch after resume, fork, or tree navigation.
3. If the state is paused, read the reported capability, Review, or Consultation error. Correct the setting or unavailable runtime capability, then explicitly re-enable or reload as the diagnostic instructs. A pause leaves the observed agent running.
4. If `advisor_ask` is missing, confirm Advisor is enabled; disabled Advisors intentionally hide it. A paused Advisor keeps the tool visible for its diagnostic. Under `codemode.mode: "only"` it stays active but undeclared, reachable only through `codemode` scripts. Consultations wait for the active Review, return plain advice, and leave Review Backlog accounting unchanged. User cancellation does not pause Advisor; runtime failures do.
5. For missing reviews, inspect backlog and catch-up configuration. Backlog counts completed model responses with their tool batches, including work under review. `off` never waits; a positive threshold waits only while backlog is at least that threshold, and each wait is capped at 30 seconds. A Review has its own deadline, investigative-call limit, and `maxFindingsPerReview` limit of 1–32. Check `reviewEvery`: under `"request"` a Review runs only when the request completes, and under `N` after every N turns and at completion; a turn with a failed tool call is reviewed at once. A Catch-up Wait waits only for a running Review, so turns waiting for their cadence never block the observed agent.
6. If Context Management is loaded, verify that all three private tools—`context_notes`, `context_history`, and `context_rollover`—are explicitly granted. Any missing grant pauses Advisor before review. These tools operate on the Advisor Session's private Notes, History, and Checkpoints; they never grant access to the observed session. Confirm native settlement and checkpoint completion rather than treating an early response or `agent_end` report as completion.
7. For tool failures, compare the effective `allowedTools` list with the loaded registry. Missing names are reported and ignored; Advisor does not autogrant tools. Grant `codemode` explicitly for scripts. An inactive advice tool after extension binding pauses the Advisor. A Tool Grant covers the tool's full native interface and is not a filesystem or operation sandbox.
8. For stale, duplicated, or unsafe advice, check branch/session identity and configuration-generation changes. Advisor Sessions are separate persisted native sessions with fresh extension resources. Unsupported opaque inline/custom resources pause rather than being reused. Nits use non-interrupting context delivery and never start Corrective Turns. Running Concerns and Blockers use Pi's native steering boundary; Blockers after normal interactive completion use only tracked, budgeted Corrective Turns. Deliberately interrupted, aborted, uncertain, and headless-completed work is preserved without restart. Child correction must finish inside Minimal's owned operation.
   - If a finding never arrived, check `/advisor status` for findings awaiting re-validation: a Superseded Finding is withheld when the agent completed more turns before delivery, and the next Review reports it again only if it still applies. `catchUpThreshold: 1` makes findings arrive before the agent moves on. Status also counts Nits dropped over `maxNitsPerRequest` and findings dropped for citing no evidence or an unknown Tool-Call Reference; the Advisor Session's `advisor_report` result names the latter.
   - If findings are directives rather than defects, or lack evidence, check whether a replaced Advisor Prompt dropped the default's evidence and completed-work wording; `advisor_report` still requires evidence on every finding.
9. If a finding seems to miss tool output or schemas, remember that Review Evidence carries tool-result text but not display-only `details`, and the Context Seed's Observed Setup lists observed tools by name and one-line summary only. Grant read tools or use `advisor_ask` when the Advisor must inspect more than the observed model received. If an early finding misses older history, check `seedBudgetTokens`: the Context Seed keeps the Observed Setup, the original request, the newest turn, and the newest turns that fit, lists the observed messages it keeps, and names the observed session file for the rest.
10. If Advisor costs too much, compare the last Review's cost and the running total in `/advisor status` with the observed agent's cost. Each Review re-reads the whole Advisor Session: lower `maxSessionTokens` so Pi's native compaction keeps it smaller, or use a coarser `reviewEvery`, which delays findings. A compaction that fails or times out does not pause Advisor; the next Review instead starts a new Advisor Session from a Context Seed (`Current context seed.` in its prompt). Context Management's Rollover replaces this compaction where it is loaded.
11. On shutdown, allow only the bounded headless final drain, which waits up to one `reviewTimeoutMs` Review deadline. Verify that no hidden corrective turn starts after root completion and that native Advisor resources are aborted before disposal.

Finish when `/advisor status` shows the intended settings and the failing Review or Consultation now settles without error: a Consultation returns advice, or a Review produces an attributed finding or zero backlog. If a capability remains unsupported, report the exact diagnostic instead of bypassing native lifecycle or permission policy.
