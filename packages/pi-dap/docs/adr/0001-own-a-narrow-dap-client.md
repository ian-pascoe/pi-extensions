# Own a narrow DAP client

`@ian-pascoe/pi-dap` owns a narrow Debug Adapter Protocol client with explicit Pi settings, one active Debug Session, and configured stdio or TCP adapters. It supports the core launch, source-breakpoint, execution-control, stack, variable, evaluation, status, and stop workflow while deliberately excluding adapter discovery, an adapter catalog, `launch.json`, attach, advanced protocol operations, persistence, and a directly operated debugger UI. Its non-authoritative Observer UI may present activity and results already received, but it sends no Debug Adapter request and offers no human debugger controls. The Supported `vscode-js-debug` workflow may open its one adapter-requested primary target channel against the same owned adapter process; unrelated, second, and nested `startDebugging` requests remain rejected. This trades protocol breadth for a small testable lifecycle while preserving one model-facing Debug Session and first-class Node compatibility.
