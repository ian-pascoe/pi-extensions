# One Pi tool per DAP operation

Each DAP operation is its own Pi tool, named `dap_<operation>` and grouped under the `dap` namespace. This replaces the single `dap` tool, which had one operation-discriminated schema. Every tool still acts on the one model-facing Debug Session from ADR-0001. Splitting the tools does not add sessions. Per-operation tools give codemode small declarations and give permission extensions exact annotations: for example, `dap_evaluate` and `dap_launch` can run arbitrary code, but `dap_stack` cannot. A core set of tools is declared directly; the rest are reachable through codemode. The `dap` tool is removed without an alias, in a breaking minor release.

Debugging is interactive, so every operation the model uses between stops is `direct`: launch, set_breakpoints, continue, next, step_in, step_out, stack, variables, evaluate, status, and stop. Only `dap_pause` is long tail: it is needed only after an execution wait times out, and `dap_stop` remains direct for a runaway Debuggee. `dap_pause` uses `codemode` rather than `deferred` exposure, so codemode lists it with its type under the namespace while `tool_search` can still load it. Neither codemode nor `tool_search` is on by default; the fallback is to activate it by name with `defaultTools: ["+dap_pause"]` or `--tools`, which Pi accepts for inactive extension tools.

Annotations follow behavior. `dap_stack`, `dap_variables`, and `dap_status` are read-only and closed world; draining unread Debuggee output is Pi DAP bookkeeping, not a change to the Debuggee. `dap_launch` and `dap_evaluate` run arbitrary code, so they are destructive and open world. Continue and stepping only advance the program approved at launch, so they are neither destructive nor open world. `dap_set_breakpoints` replaces Pi DAP's own Desired Breakpoints, so it is idempotent and not destructive. `dap_stop` is destructive and idempotent.

Each tool declares an `outputSchema` and returns `structuredContent` with complete data: state, all drained Debuggee output, Desired Breakpoints, and every row of the operation's result. Version 0.3.6 removed an output schema because it described only the bounded Observer UI details, which would have replaced complete results in codemode scripts; the details stay bounded and separate. A Debug Session state failure returns `isError` with the current state instead of throwing, so scripts can read it. All tools execute sequentially because they share the Debug Session.

Pi shows namespace `instructions` only to codemode and `tool_search`, and Pi 0.99.0 ignores the field. Each description therefore states its own rules, and one shared prompt guideline covers the family. The declared core costs about twice the characters of the single `dap` tool. Exposure, namespaces, annotations, and output schemas require Pi 0.99.0 or later.
