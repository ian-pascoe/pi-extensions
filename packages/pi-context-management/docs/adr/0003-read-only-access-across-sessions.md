# Read other sessions' Notes and History, never write them

Notes and History remain owned by one session branch, but `context_notes` and `context_history` accept a Search Scope (Branch by default, Lineage, Repository, or All) that reads other sessions. Reads never write: a session writes only its own journal, because a second session manager appending to another session's file would desynchronize that session's in-memory journal. A parent shares nothing by push; it reads a child's Lineage Notes live and may `copy` one into its own Notes as an unlinked snapshot, so Notes deleted with a Child Agent survive only where copied.

Other sessions are read as their latest branch, parsed from file contents without `SessionManager.open`, which can migrate and rewrite files; a partial final line from a live session is ignored. Pi groups sessions by working folder and records nothing about git, so each session records its repository's main worktree once, and older sessions are matched by resolving their recorded folder; sessions whose folder is gone and that lack the record appear only in the All scope. Repository and All scopes run newest session first, ordered by Pi's creation-time file names so writes to running sessions do not reorder pages; the Lineage scope runs ancestors nearest first, then descendants. Searches page with `next_offset` and build no index, consistent with deriving state from Pi sessions. Sessions are listed by reading Pi's session directories rather than through `SessionManager.listAll`, which parses every file in full to build its summaries before a search could stop early. The Note Index lists only the agent's own Notes.
