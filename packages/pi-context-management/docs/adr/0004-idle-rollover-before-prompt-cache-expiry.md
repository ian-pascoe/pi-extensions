# Idle Rollover before the prompt cache expires

A large Context Window left idle past its provider prompt cache lifetime makes the user's next message resend the whole window uncached. Pi 1.1.0 has no idle compaction trigger, so Context Management owns one narrow timing policy: when an interactive session settles with native context usage of at least `contextManagement.idleRollover.minTokens` (default 200,000, enabled by default), it starts a pausing Rollover at Pi's own cache refresh point, while the preparation request still reads the cached prefix. This reopens [ADR-0002](0002-let-pi-own-compaction-policy.md)'s "Pi owns compaction timing" for this case only; Pi still owns accounting, thresholds, retention, and overflow.

Pi stays the owner of cache lifetime and warming. The timer uses the model's `promptCache` tier that `PI_CACHE_RETENTION` selects and Pi's 90% refresh formula, copied because Pi does not export it. While Pi's `cacheWarming: "idle"` mode keeps the cache warm, Idle Rollover follows each recorded `cache_warm` usage entry and Pi's `cacheWarmingStatus`, and runs only once warming stops; it never overrides `cache_warming_decision`. A check past Pi's late-refresh cutoff does nothing, because the cache is likely cold and a Rollover would no longer be cheap.

Idle Rollover is not a background summarizer: it is the existing Manual Rollover preparation, an ordinary agent turn that refreshes Notes and writes a Handoff. Input that arrives during it is requeued as a follow-up so it runs after the checkpoint in the new Context Window instead of steering the preparation. Failure reports noncompletion like other preparation but neither retries until the user starts another run nor suppresses later threshold preparation. Print-mode runs, including Child Agents, never arm it, since no user returns to them.

Settings live in this extension's own `contextManagement` namespace, which Pi does not define; the obsolete-settings warning now applies only to keys other than `idleRollover`. Considered and rejected: rolling over only on the long (one-hour) cache tier, which would leave Pi's default five-minute tier without the feature; and acting from `cache_warming_decision` alone, which Pi emits only while cache warming runs.
