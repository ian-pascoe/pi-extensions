# Use native compaction checkpoints for every rollover

Every Rollover should commit a native Pi compaction checkpoint so the parent, session resume, forks, and existing Subagent inheritance share one persisted definition of the active Context Window. Public compaction hooks cover native manual, threshold, and overflow paths, but arbitrary-time Rollover requires a narrow, version-checked integration beyond the extension-facing read-only session interface; we accept prototyping that integration rather than introducing virtual-only checkpoints, modifying downstream consumers, or weakening Rollover into deferred-only compaction. The adapter must prove coherent live and persisted state and failure handling before implementation builds on it; direct session-file editing is excluded. The production adapter is pinned to Pi 0.85.1 and preserves normal preflight/context transforms when refreshing the active loop. Write failures stop requests and quarantine the loaded journal until it is reopened from disk; resource reload is not transactional recovery. This accepted fail-closed behavior does not promise rollback of Pi's speculative in-memory entries.
