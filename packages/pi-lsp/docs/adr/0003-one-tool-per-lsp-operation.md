# One Pi tool per LSP operation

Each LSP operation is its own Pi tool, named `lsp_<operation>` and grouped under the `lsp` namespace. This replaces the single `lsp` tool, which had one operation-discriminated schema. Now that codemode can call tools from scripts, each tool can carry its own small declaration and exact tool annotations. Permission extensions can then tell read-only queries apart from the destructive `lsp_apply`. Before, the model had to read a table of required fields per operation, and every call had one generic risk profile.

Ten core tools are declared to the model (`direct` exposure): `lsp_status`, `lsp_diagnostics`, `lsp_hover`, `lsp_goto_definition`, `lsp_find_references`, `lsp_document_symbols`, `lsp_workspace_symbols`, `lsp_rename`, `lsp_code_actions`, and `lsp_apply`. They cover the read queries agents use for navigation and diagnostics, and the two edit producers whose results agents act on. `lsp_apply` must be declared so that every Workspace Edit Preview, including one in a resumed session, can be applied. `lsp_status` is in the core because it is step 2 of the user-invoked troubleshooting Skill (ADR-0005 of the repository); its first diagnostic step must not depend on `codemode` or on the user running `/lsp` (which remains an option). We kept `lsp_capabilities` and `lsp_restart` out: they are later diagnosis and recovery steps that scripts and `tool_search` reach, and the user has `/lsp stop` for recovery. The formatting previews stay out too, since Pi Formatter owns routine formatting.

## Long-tail exposure

The other 25 tools use `codemode` exposure rather than `deferred`. Pi lists `codemode` tools, with TypeScript declarations grouped under their namespace, in the `codemode` tool description, so scripts can call them without a search. `tool_search` still finds and declares both kinds. The listing shares the `codemode.inlineBudget` (3000 estimated tokens by default) with other extensions; tools that do not fit stay findable with `searchTools()` and `describeNamespace("lsp")` (`describeNamespace` exists only in Pi 1.0 and later).

Neither `codemode` nor `tool_search` is on by default. Without them, the fallback is activation by name: Pi activates an inactive extension tool named in `defaultTools` (`"+lsp_capabilities"`) or `--tools`. The README and the troubleshooting Skill document all three paths.

## Shared rules

The rules every tool shares (one-based Unicode coordinates, an optional leading `@` in paths, Result Spill, preview-then-apply, server selection) live in `namespace.instructions` for scripts. Pi 0.99 has no `instructions` field and never shows it for declared tools, so the rules also reach the model as one identical `promptGuidelines` entry on every tool, which Pi deduplicates. The facts a call cannot be correct without stay on the tool itself: `line` and `character` are described as one-based in their schemas, and each preview tool's description names `lsp_apply`. Custom system prompts that drop guidelines therefore still see them.

`lsp_diagnostics` alone also has a short `promptSnippet`, as the Pi DAP tools do for `dap_launch`. Pi's default system prompt lists only tools that have a snippet under "Available tools", so without one LSP would not appear there at all. A single snippet keeps that list to one LSP line, and it names the `lsp_*` family. Pi ignores snippets when the system prompt is customized; the guideline still applies.

## Annotations

Queries, `lsp_status`, and `lsp_capabilities` are read-only, idempotent, and closed-world. `lsp_capabilities` stays read-only although it can start a server, because it changes no file or data. The preview producers (`lsp_rename`, `lsp_code_actions`, `lsp_format_*`) are also read-only: they only record a session-local Workspace Edit Preview, and no file changes until `lsp_apply` runs with its verified Mutation Manifest (ADR-0002). This lets permission extensions confirm only the call that writes. They are not idempotent, since every call creates a new `preview_id`. `lsp_restart` changes no data but is not read-only; it is idempotent (restarting twice leaves one running server) and non-destructive. `lsp_apply` is destructive and not idempotent.

All tools set `openWorldHint: false`. MCP's open-world hint marks tools that reach an unbounded set of external entities, such as the web. These tools talk only to language servers that the user configured as local commands, so the set of entities is closed, even though a configured server could in principle call the network. A permission extension that wants to treat servers as untrusted should use the server configuration, not this hint.

## Structured results

Every tool declares an `outputSchema` and returns matching `structuredContent`. An earlier release removed the single tool's output schema because it described only the result details, which omit raw protocol payloads, so codemode scripts would have received less than the text. The structured results now carry the complete data (complete for the requested depth or limit where a call bounds it): each server's normalized response for reads, and full preview and apply data for mutations. Pi keeps `structuredContent` out of model context and session history, so the model-facing output limit does not cut it. It has its own cap of 1 MiB, like Pi's built-in `bash` tool. A larger result is bounded deterministically: the longest strings are shortened (with a `…[n characters truncated]` marker) and the longest arrays lose their tails, with limits that tighten step by step until the result fits. Location, symbol, and hierarchy items also carry flat one-based `path`, `line`, and `character` (and symbols a `kind_name`) beside the protocol fields, so a script passes an item straight to a position tool; model-visible text never shows them. Identifying and enum fields (`state`, `operation`, kinds, ids, paths, `server_preview_ids`) are never shortened, and the last step empties strings and arrays rather than dropping fields, so the bounded result still matches the `outputSchema`.

A bound the caller chooses is part of the query, not truncation. `lsp_document_symbols` takes `depth` (default 1, or `"all"`) and cuts the server's tree before it is normalized, so its text and structured result both follow the requested depth: declarations and the members of classes, interfaces, enums, namespaces, modules, packages, objects, and structs, without the locals, return-object properties, and callbacks inside function, method, and variable bodies. A flat `SymbolInformation[]` response is cut the same way through `containerName`. The count of nested symbols left out is `omitted` in the structured result and a closing line of the text, so the model knows `depth: "all"` exists. `lsp_completion` and `lsp_workspace_symbols` keep at most `limit` items per server (default 50), and completion keeps only items starting with `prefix` (by default the identifier before the position). Their structured value is the server's response with only the kept items, plus `prefix` and the count of `omitted` matching items. Unbounded lists reached tens of kilobytes of rarely relevant items, each resolved one request at a time. A script that needs more items raises `limit`.

Two flags report what was cut. `structured_truncated` is `true` only when the structured data was bounded; when it is `false`, scripts hold complete data even if the model-visible text was cut. `truncated` is `true` when either the model-visible text or the structured data was cut. A bounded result also appends a warning to `warnings` where the tool has one. `spill_path` names the Result Spill. When the structured data was bounded, the spill holds the complete structured data as JSON, so everything the bounded result lost (`mutation_manifest`, `changed_paths`, created, deleted, and renamed files, protocol payloads) stays recoverable; the model-visible text is derived from the same data. When only the text was cut, the spill holds the complete text. `tool_result` handlers that append text (Post-edit Diagnostics, Pi Formatter) return the structured result with the new content, because Pi otherwise drops it.

An `lsp_apply` partial failure returns `isError: true` with its structured result, so scripts receive `state: "partial_failure"` and the changed paths. Post-edit Diagnostics no longer changes the error state.

## Considered Options

- **Keep the single tool.** Rejected: codemode would still show one large union, and annotations could not differ per operation.
- **Group related operations** (hierarchies, formatting). Rejected: grouping brings back operation-specific field rules and mixed annotations.
- **Keep `lsp` as a hidden alias for one release.** Rejected: the package is pre-1.0, and an alias would keep two contracts in circulation.
- **Use `deferred` exposure for the long tail.** Rejected: deferred tools are never listed for codemode scripts, which would have to search before every call.

## Consequences

The `lsp` tool is removed without an alias, in a breaking minor release. Code that reads tool results (preview replay, Post-edit Diagnostics, and the formatter in `pi-formatter`) recognizes results by details kind plus a tool-name allow-list that includes the legacy `lsp`, indefinitely, so resumed sessions keep their Workspace Edit Previews and apply them with `lsp_apply`. Legacy results render with Pi's default renderer. Settings that grant `lsp` by exact name must be updated. Declaring ten tools costs about 330 more tokens than the single tool did, and with codemode active the namespace listing adds up to its share of the inline budget.
