# Keep MCP configuration in Pi settings

`@ian-pascoe/pi-mcp` reads a package-owned `mcp` object from Pi's global and trusted project `settings.json` layers instead of using a standalone MCP configuration file or the common top-level `mcpServers` shape. The object begins with `servers`, bounded host-wide `retry`, `connectTimeoutMs`, and `requestTimeoutMs`; it can gain only other concrete package-wide settings. Global and project retry fields merge individually. Server maps merge by name, while a project Server Definition replaces the complete same-named global definition. A project entry containing only `{ "enabled": false }` masks an inherited definition without copying it; `null` remains an accepted equivalent for hand-written settings. A complete disabled definition retains its connection details. A command infers stdio, a URL infers Streamable HTTP, and the optional `transport` field makes stdio, HTTP, or legacy SSE explicit. Local process overrides use the repository-wide `environment` term. This trades cross-client configuration portability for Pi's existing settings locations, project-trust boundary, and room for host-wide settings without polluting Pi's top level.

The initial Server Definition schema has only `command`, `args`, `cwd`, `environment`, `url`, `headers`, `transport`, `auth`, and `enabled`. Transport values are `stdio`, `http`, and `sse`; command and URL definitions are mutually exclusive. Retry and request deadlines remain host-wide rather than per-server.

Retry defaults are `maxRetries: 2`, `initialDelayMs: 1000`, `maxDelayMs: 30000`, and `backoffFactor: 1.5`; `maxRetries: 0` disables retry. Connection and request deadlines default to 10,000 ms and 60,000 ms, progress resets the request deadline, and shutdown has a fixed five-second bound.

The standalone CLI uses Pi's saved project trust and `--approve` or `--no-approve` semantics before changing project settings, denying headless project writes without approval. Project-scoped disable writes `{ "enabled": false }` for an inherited server; enable removes that override, and removing a project definition may reveal its global predecessor. The CLI and `/mcp` command share the same noninteractive syntax, list, add, remove, enable, disable, authentication, logout, and test operations and preserve unrelated settings with locked atomic writes. Add accepts a remote URL or a local command after `--`, with repeated header, environment, and OAuth scope options. Both surfaces default mutations to global settings, with `-l` or `--local` selecting project settings. Standalone read-only commands additionally support `--json`. Standalone mutations have no watcher and require `/reload` in a running Pi process; successful `/mcp` mutations also update the current session immediately. Add and enable connect in the background, while disable and remove disconnect and deactivate. Connection failure never rolls back valid persisted settings, and the frozen Instruction Snapshot never changes.

The `mcp` schema is strict while unrelated Pi settings remain untouched. An unknown or invalid MCP field prevents MCP servers from starting and appears in `/mcp status`, but the extension always contains that failure so Pi startup and TUI rendering continue. Standalone CLI validation failures exit nonzero.
