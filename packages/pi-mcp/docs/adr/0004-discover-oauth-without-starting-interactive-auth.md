# Discover OAuth without starting interactive authorization

Remote Server Definitions use a discriminated `auth` object: `none` disables authentication discovery, `bearer` supplies an interpolated static token, and `oauth` enables discovery with optional client metadata. An omitted `auth` first connects unauthenticated and recognizes standards-compliant OAuth from the server's challenge and protected-resource metadata. Background discovery may mark a server `needs_auth` but never opens a browser; only an explicit CLI or `/mcp auth` action starts authorization.

OAuth uses a fixed loopback callback by default and accepts an explicitly pasted full callback URL, or an authorization code paired with its returned state, for remote environments. The Host never accepts a bare code that bypasses state verification. OAuth entries are bound to the resolved server URL and client identity in the mode-`0600` `mcp-auth.json` store. Malformed authentication storage becomes an authentication error and is never silently replaced; Pi still starts, but authentication mutations require repair or explicit `logout --all --force` reset. Removing a Server Definition retains credentials unless the user also requests logout.
