# Skip claimed turns in default `subagent_wait` selection

Without `turn_id`, `subagent_wait` selects the oldest observable turn whose result the parent has neither claimed nor been handed, in Delivery Ledger sequence order, and falls back to the active turn, then the latest turn, when none remains. This supersedes the default-selection rule of [ADR-0001](0001-wait-event-delivery-ordering.md), which prioritized the oldest claimed turn. That rule made the documented workflow (claim a result, `agent_message` the idle child, wait on the `started-turn`) return the already-claimed first result again, both while the new turn ran and after it was cancelled.

ADR-0001 otherwise remains in force. An explicit `turn_id` addresses any turn whose result is still retained, claimed or not, and returns the same settled result on repeated waits. A claimed wait-only terminal result stays retained, bounded at 20 per source per [ADR-0003](0003-persisted-delivery-ledger.md), until Delivery Evidence settles it; the wait's own tool result is that evidence, so once the wait is recorded and a newer turn has settled, an explicit wait on the older turn fails as no longer retained. A result counts as handed once automatic fallback has queued it to the parent, even before Delivery Evidence is reconciled; this is process-local, and a reload either settles the result by its evidence or hands it over again. A result that has not yet been handed, such as one still inside the wait-claim grace period or whose delivery failed, stays selectable, and waiting for it claims it. Claims remain durable Delivery Ledger state and behave as before across reloads and forks; automatic fallback is unchanged. Unclaimed settled turns are still returned oldest first.

## Consequences

ADR-0003 said a newer turn cannot strand an older claimed turn. That no longer holds for default waits. A turn claimed without Delivery Evidence, for example after a crash between the claim and the append of the wait's tool result, is never delivered automatically, and once a newer turn exists only an explicit `turn_id` reaches it. We accept this: the old rule broke the ordinary message-then-wait workflow on every use, while the stranded case needs a crash in a narrow window and stays recoverable by `turn_id`.
