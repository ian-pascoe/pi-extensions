# Deliver Coordination Messages through ordered Wait Events

`subagent_wait` is the synchronization seam between a parent and a direct Child Agent. When that child sends a Coordination Message to its direct parent, an active wait resolves with an intermediate `event: "message"` Wait Event. The message is not also sent through Pi's steer queue. If the turn has already settled when the parent waits, one terminal `event: "turn"` drains queued Coordination Messages into its `messages` field. If `timeout_ms` expires first, an observational `event: "timeout"` returns the requested turn identity and the same detailed Child Agent status used by targeted `subagent_status`.

A successful message wait claims only that Coordination Message. Later messages and the terminal result retain automatic fallback unless another active wait receives them. Terminal wait claims, pending items, and global delivery sequence survive reloads, forks, and newer child turns. Optional `turn_id` addresses one retained turn exactly; default selection prioritizes the oldest claimed or otherwise observable turn. A timeout removes only that waiter without claiming delivery or cancelling the child; abort cancellation still rejects and removes only its waiter. A second concurrent wait from the same caller for that source turn is rejected rather than racing the first waiter.

Turns without a wait claim use automatic fallback. Every item persists before `agent_message` reports `queued`, reserves its recipient-queue position by sequence, and remains pending until destination-session Delivery Evidence exists. After a short grace period in which a direct parent may claim an item with `subagent_wait`, the coordinator batches queued messages from the same source turn into one Pi steer. Root-bound messages remain batchable while the root turn is active, and a pending terminal result absorbs them into the same result steer. Child sessions drain all available steers before their next model call, avoiding one model turn per queued item.

Stable delivery IDs make replay idempotent. Wait tool-result evidence and typed custom-message evidence settle exact items; batched steers carry every included message ID. The process-local handed marker is installed before queue delivery, so synchronous evidence settlement removes it without a post-settlement leak. Settled items are removed from live checkpoints; deleting an agent subtree prunes associated pending items. Wait-only terminal history is bounded to 20 items per source without pruning Coordination Messages. Tool results report queue acceptance as `queued`; only a wait handoff is `delivered-via-wait`.
